# Field Relay adaptation

Inspected Field Relay `origin/main` at `7d490809754bc33d4f17f94e55c59ced14a13b66`, including `docs/integration/CONTRACT.md`, `docs/integration/INTERVIEW_GUIDE.md`, `docs/INTERFACE_RELEASE_2026-10-15.md`, and `integration/relay/contract.ts`, `retry.ts`, `dispatch.ts`, and `transport.ts`. The invoice lab is newly authored and adapts the contract's stable business identity, separate payload digest, approval-bound admission, receiver-side deduplication, separate SQLite stores and authoritative readback. It is not a copy of the full Field Relay implementation or its original order experiment. Field Relay was not modified.

The smaller invoice harness is intentionally narrower: the recording script runs a bounded retry sequence after a request-correlated absence; there is no background worker or Field Relay lease and complete transport hardening. It honors Retry-After on a transient response or correlated readback and holds waits beyond its deadline. A generic 404 never triggers a new write. Its local session uses a randomly generated in-memory bearer token, and SQLite approval, scoped rule lifecycle and attempt counters persist across relay process restarts. It is not a production financial system. The browser simulation is separate and does not write to either local store.

All fixtures are synthetic. The separate model record in `public/evidence/model-proposals.json` contains local Qwen proposals and their validation; incorrect coding remains held. Document text has no authority to approve or dispatch. The original evaluation is authored by the same implementation team, and its public cases are known replays rather than independent or newly hidden validation. The record's `working-tree-sha256` hashes the named implementation files, not a Git commit; regenerate it after edits.
