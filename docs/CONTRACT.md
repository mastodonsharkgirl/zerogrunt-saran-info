# Shared presentation and evidence contract v1

Scenario IDs: `context`, `recovery`, `correction`, `evaluation`.
Fixture ID `invoice-000184`, entity `NORTHSTAR-IN`, vendor `PAPERCARE-01`,
invoice ID `000184`, currency INR, amountMinor 125000, purpose printer-maintenance.
Allowed coding `OFFICE-OPS`, `FACILITIES`; policy approvers `operator`, `controller`.
Stable identity includes entity, vendor and original invoice ID; payload digest
is separate. Preserve leading zeros.

Workflow states: awaiting_review, ready, sending, outcome_unknown, retry_waiting,
verified, held, terminal_failure. A context or payload revision invalidates
approval before admission. Approval binds actor, expiry, exact payload and
authoritative policy/rule revision. ERP commit survives a lost response.

Correction: proposed -> approved_for_testing -> evaluated -> active/rejected;
withdrawn stops future application. Digest binds scope, condition, action,
effective interval and policy revision. One-off is default. Testing and
activation are separate human decisions. Policy always outranks convenience.

Browser has no durable side effect. Its controls demonstrate the same named
contracts using fixed synthetic inputs. Reset returns initial memory state.
Recorded HTTP run is generated by `npm run lab:record` at
`public/evidence/http-run.json`; frozen evaluation by `npm run evaluate` at
`public/evidence/evaluation.json`. Evidence must carry schemaVersion,
generatedAt, sourceRevision, command, fixture identifiers, individual outcomes
and metric numerators/denominators. Rendering must tolerate missing evidence
by showing unavailable rather than a success.

Exact result properties will be communicated by the workflow implementer
before presentation integration. No numerical success placeholders.
